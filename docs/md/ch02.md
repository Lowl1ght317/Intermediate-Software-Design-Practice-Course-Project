# 2  需求分析

## 2.1 需求获取方法与过程

本项目为单人完成的课程实作，需求获取在两周内分三轮完成，力求每条需求都能追溯到具体来源，而不是凭空设想。

**第一轮：课程要求拆解。** 把《作业选题》中“课题一”的 9 条要求逐条转写为候选需求，形成“强制需求池”，确保课程的硬性指标不遗漏。这一轮确定了产品、物料、BOM、编码规则、编码服务、APP 拆分六条主线。

**第二轮：现场访谈与观察。** 以本校文创工作室为对象，访谈工作室负责人、制作师傅、仓库管理员各 1 人，并在制作间观察一次批量制作过程。访谈围绕三个问题展开：现在怎么编号、怎么做 BOM、怎么跟进度。观察的重点是“一件产品从接单到入库要经过哪些动作”，用以确认工单状态。

**第三轮：原型确认。** 依据前两轮结果绘制页面草图与用例图，请工作室负责人确认“哪些字段必须有、哪些流程可以砍”。这一轮删去了库存台账、供应商管理、图片管理等超出范围的功能，把范围收敛到主数据与工单。

需求来源与编号的对应关系为：课程要求对应 F01—F09，访谈与观察对应 F10—F14，业务规则 BR01—BR08 来自访谈中的原话（如“编码定了就不能改”）。

## 2.3 用户角色与职责

| 角色 | 职责 | 主要权限 | 对应岗位 |
| --- | --- | --- | --- |
| 文创设计员 | 维护文创产品与产品 BOM，提交打样与批量制作需求 | 产品、BOM 的增删改查；物料只读；工单可创建不可下达 | 设计师 |
| 生产主管 | 审核用料、下达工单、跟踪完工 | 工单的创建、下达、完工；产品与 BOM 只读 | 工作室负责人 |
| 仓库管理员 | 维护物料主数据，按工单备料 | 物料的增删改查；工单只读 | 库管 |
| 系统管理员 | 配置编码规则、维护角色与菜单授权 | 编码规则增删改查；角色菜单授权；全部数据只读 | 平台管理员 |

四个角色之外不设“访客”，未登录用户无法进入系统。角色与菜单的绑定通过平台自带的权限中心完成，业务代码中不硬编码角色判断。

## 2.4 用例图与用例规约

![图 2-1  校园文创产品生产管理系统用例图](figs/fig2-1_usecase.png){width=14.5cm}

系统的用例视图如图 2-1 所示。四个参与者与八个用例的对应关系为：设计员负责产品与 BOM 的维护，生产主管负责工单的下达与完工，仓库管理员负责物料维护，系统管理员负责编码规则与授权。产品维护、BOM 维护、工单下达三个用例在执行时都会包含“生成业务编码”，因此该用例被三个用例以 «include» 关系复用。

以下给出三个核心用例的详细规约，其余用例的规约见附录 A。

**用例 UC-01：维护产品 BOM**

| 项目 | 内容 |
| --- | --- |
| 用例编号 | UC-01 |
| 参与者 | 文创设计员 |
| 前置条件 | 已登录且具有产品维护权限；目标产品已存在；所需物料已录入 |
| 基本流程 | 1. 设计员在“文创产品”列表中选择一条产品，点击“编辑”；2. 系统打开产品表单，切换到“BOM 明细”标签页；3. 设计员点击“新增行”，选择物料并填写用量；4. 系统校验物料不重复、用量大于 0；5. 设计员点击“保存”，系统写入 BOM 明细并刷新表单 |
| 异常流程 | 3a. 所选物料已存在于当前产品的 BOM 中，系统提示“该物料已在 BOM 中”，拒绝新增；4a. 用量为空或不大于 0，系统提示“用量必须大于 0”，阻止保存 |
| 后置条件 | 产品的 BOM 明细被持久化，产品列表中的“物料种数”随之更新 |
| 业务规则 | BR03、BR04、BR05 |

**用例 UC-02：生成业务编码**

| 项目 | 内容 |
| --- | --- |
| 用例编号 | UC-02 |
| 参与者 | 系统（由产品保存、物料保存、工单下达触发）；系统管理员可手工试算 |
| 前置条件 | 目标编码规则存在且处于启用状态 |
| 基本流程 | 1. 业务保存时调用编码生成服务，传入规则标识；2. 服务读取规则的前缀、日期格式、分隔符、流水位数；3. 服务按当前日期计算日期段，查询该规则当日已用的最大流水号；4. 流水号加 1，按位数左补零，与前缀、日期段、分隔符拼接；5. 服务返回编码，业务保存该编码 |
| 异常流程 | 1a. 规则不存在或已停用，服务返回错误“编码规则不可用”，业务保存失败；3a. 同一规则并发取号时，后到请求等待行锁，取到下一个号，不产生重复编码 |
| 后置条件 | 编码唯一写入业务表；流水号表当前值加 1；编码一经生成不允许修改 |
| 业务规则 | BR01、BR02、BR06 |

**用例 UC-03：下达与完工工单**

| 项目 | 内容 |
| --- | --- |
| 用例编号 | UC-03 |
| 参与者 | 生产主管 |
| 前置条件 | 已登录且具有工单下达权限；目标产品已维护 BOM |
| 基本流程 | 1. 生产主管新建工单，选择产品、填写计划数量与要求完工日期；2. 系统按 BOM 折算本次所需物料并展示；3. 主管点击“下达”，系统将状态由“草稿”改为“已下达”并生成工单编码；4. 制作完成后，主管点击“完工”，填写实际完工数量；5. 状态改为“已完工”，工单锁定为只读 |
| 异常流程 | 1a. 产品未维护 BOM，系统提示“请先维护产品 BOM”，禁止下达；4a. 实际完工数量大于计划数量且超过 10%，系统提示确认，需二次确认才允许保存 |
| 后置条件 | 工单状态与完工数量被记录，可按状态统计生产进度 |
| 业务规则 | BR07、BR08 |

## 2.5 功能需求清单

优先级采用 MoSCoW 口径：“必须”为交付底线，“应该”为演示加分，“可选”为时间允许时补充。

| 编号 | 功能名称 | 功能说明 | 优先级 | 对应课题要求 |
| --- | --- | --- | --- | --- |
| F01 | 文创产品管理 | 产品的新增、编辑、删除、查询；字段含名称、规格、状态、编码 | 必须 | 第 1 条 |
| F02 | 物料管理 | 物料的新增、编辑、删除、查询；编码唯一约束；字段含名称、规格、单位 | 必须 | 第 2 条 |
| F03 | 产品 BOM 维护 | 在产品表单的 BOM 标签页维护明细，明细含物料与用量 | 必须 | 第 3 条 |
| F04 | BOM 增删 | BOM 明细行可新增、可删除，保存时整体提交 | 必须 | 第 4 条 |
| F05 | 编码规则管理 | 编码规则的增删改查，字段含规则标识、前缀、日期格式、分隔符、流水位数、启用状态 | 必须 | 第 5、6 条 |
| F06 | 编码生成服务 | 后端服务按规则生成编码，并通过接口提供给业务调用 | 必须 | 第 7 条 |
| F07 | 业务编码接入 | 产品、物料、工单的编码均由编码服务生成，保存时自动赋值 | 必须 | 第 7 条 |
| F08 | 编码试算 | 页面提供“试算”按钮，展示按当前规则生成的下一个编码示例 | 应该 | 第 6 条 |
| F09 | APP 拆分 | 按业务域拆为 cw-base、cw-prod、cw-sys 三个 APP，各自有独立菜单 | 必须 | 第 9 条 |
| F10 | 生产工单管理 | 工单的新增、编辑、查询；字段含产品、计划数量、要求完工日期、状态 | 必须 | 第 8 条 |
| F11 | 工单状态流转 | 草稿→已下达→已完工，状态变更受业务规则约束 | 应该 | 第 8 条 |
| F12 | 用料折算 | 工单下达时按 BOM 与计划数量折算所需物料清单 | 应该 | 第 3、8 条 |
| F13 | 角色与菜单授权 | 四个角色按最小权限授权到菜单与按钮 | 必须 | 课程通用要求 |
| F14 | 模块化菜单 | 每个 APP 一个根菜单，子菜单按模型组织 | 必须 | 第 9 条 |

## 2.6 业务规则

| 编号 | 规则描述 | 来源 | 落地方式 |
| --- | --- | --- | --- |
| BR01 | 编码由“前缀 + 日期段 + 分隔符 + 定长流水号”构成，同一规则内编码唯一 | 课程要求第 5、6 条 | 编码规则表 + 流水号表，唯一索引 |
| BR02 | 编码一经生成不可修改，只能作废后重新生成 | 访谈第 6 条 | 表单中编码字段设为只读 |
| BR03 | 产品的 BOM 至少包含一行明细才能下达工单 | 访谈第 2 条 | 下达前校验明细数量 |
| BR04 | BOM 明细的用量必须大于 0 | 访谈第 3 条 | 字段校验 + 保存前校验 |
| BR05 | 同一产品的 BOM 中，同一物料只能出现一次 | 业务常识 | 保存前按物料去重校验 |
| BR06 | 日期段变化时流水号从 1 重新开始 | 课程要求第 6 条 | 流水号按“规则 + 日期段”存储 |
| BR07 | 工单计划数量必须为正整数，要求完工日期不得早于当天 | 访谈第 8 条 | 字段校验 |
| BR08 | 已完工的工单不可再编辑，只能查询 | 访谈第 7 条 | 状态为已完工时表单只读 |

## 2.7 非功能需求

| 类别 | 要求 | 验证方式 |
| --- | --- | --- |
| 性能 | 单表数据量 1000 行以内时，列表查询响应时间不超过 1 秒 | 造 1000 行数据后计时 |
| 并发 | 同一编码规则被并发调用时，不产生重复编码 | 用脚本并发调用编码服务 50 次，检查编码是否重复 |
| 易用性 | 常用操作不超过三次点击；表单必填项有星号与提示 | 按演示脚本走查 |
| 兼容性 | Chrome 100+ 与 Edge 100+ 可正常使用，分辨率 1366×768 起 | 两种浏览器各走一遍 |
| 安全性 | 未登录不可访问；四个角色只能看到授权菜单；编码规则仅管理员可改 | 用四个账号分别登录验证 |
| 可维护性 | 新增一个业务模型只需增加模型类与视图 JSON，不改引擎代码 | 以工单模型为例说明 |
| 可移植性 | 更换数据库只需修改连接配置，不修改业务代码 | 修改 dbcp.properties 指向新库验证 |

## 2.8 需求裁剪与优先级确认

| 裁剪结论 | 功能 | 理由 |
| --- | --- | --- |
| 必须做 | F01—F07、F09、F10、F13、F14 | 覆盖课题 9 条硬性要求与评分口径，缺一不可 |
| 应该做 | F08、F11、F12 | 提升“逻辑完成度”的观感，工作量可控 |
| 可选 | 首页看板、物料安全库存预警、工单导出 Excel | 有余力再做，不影响评分主线 |
| 不做 | 商城下单、支付、物流、评价、图片管理、采购与供应商、库存台账、多工厂隔离、移动端打包 | 超出“把产品做出来”的范围，且两周内无法保证质量 |
